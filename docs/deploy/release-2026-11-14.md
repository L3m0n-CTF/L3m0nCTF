# Release `release-2026-11-14`: what is in it, and how it is put on the cloud

This is the release for the second go-live. The exact steps, in order and with who does each, are in [go-live-2026-11.md](go-live-2026-11.md). **It is a first install on a new machine and a new database, not an upgrade**: nothing runs from an earlier release, so the database is created and migrated from nothing at the first start.

## What is new since `release-2026-11-03`

- **For a player:** a Stories page (`/stories`, linked from the Guide) that opens the cold-open comics and the finale; a programme can carry a one-line story (at most 280 characters) that the panel shows; the finale can open by itself at a time the crew sets (`l3mon_finale_at`); a request refused for coming too fast now shows the L3m0n-TV "slow down" page instead of a bare error (piece E, merged on 4 November).
- **For the crew:** the second half of the instancer is in the code and tested: the TCP relay in the router, two-hop HTTP routing, the challenge-host kit (`deploy/challenge-host`), several challenge hosts with a shared host-down mark and per-host tokens, the host firewall rules and their reboot unit, and the packing test (piece F, merged on 9 November). **It is not switched on in the day-one stack**: it needs a second machine and the real challenges (see go-live-2026-11.md, part 9.3).
- **Under the hood:** the image upgrades `apt` and `libapt-pkg6.0` to Debian's fixed 2.6.2 (CVE-2026-109518) and `tools/verify-image.sh` checks the version; the CI scan of the three third-party images accepts three more advisories in the pinned nginx image (musl, zlib, libexpat) and, since 14 November, three in libxslt, each **checked on the image itself** (nginx imports none of the affected calls and loads no module; see `docs/security/dependency-bumps.md`); a CI job runs the instancer's own tests.

## The database

**One new migration:** `d8f3a1b4e205_add_story_to_programmes` (the `story` column). On a new database it runs with all the others at the first start. If an older database is ever restored into this release, take a backup first (`tools/backup.sh`); the migration runs at start.

## Day-one settings

`L3MON_ENV=production`, `L3MON_IMAGE_TAG=release-2026-11-14`, overlays `identity` and `ops` (and the `host-metrics` profile), **registration closed** (`registration = "private"` in `config/event.toml`) until the checklist in go-live-2026-11.md, part 8, is true. The machine is one VM with 4 vCPUs and 8 GB.

## Still not in it (said plainly)

- The challenges themselves (they are being collected and are integrated later).
- A mail provider (every account is confirmed by e-mail, so nobody can finish registering until one is connected).
- A challenge host and the first real instancer challenge (needs a second machine, digest-pinned challenge images and a wildcard name for instance addresses).
- Login with CTFtime (waits for CTFtime's approval and secret), and Google sign-in (waits for an OAuth client).
- Per-team downloads (this year downloads are shared files with one fixed flag; only running instances get a flag of their own per team).

## If anything is wrong

`docs/runbooks/10-rollback-deploy.md`. There is no earlier release on this machine to go back to, so the rollback for the first days is: close registration, fix, redeploy the tag, or rebuild from the encrypted state file (`docs/deploy/move-to-a-new-account.md`).

## Addendum: `release-2026-11-14b` (the crew host name replaces the list of addresses as the way in)

The project's superior refused a list of addresses for `/admin`. nginx used that list for four things (the `/admin` pages, the administrator API, uploads and the maintenance bypass), so it could not simply be removed. In `release-2026-11-14b` `$admin_net` is 1 for an address on the list **or for the crew host name** (`crew.<domain>`); the platform host name never gets it. Three integration tests prove it (the crew host reaches the surface from any address; the platform host is refused exactly as before; made-up look-alike host names get no answer), the 20 older "refused from outside" tests still pass with the crew name served, and two deliberate breaks of the rule were each caught by a test. **Cloudflare Access on the crew host is required** for this to be safe (see go-live-2026-11.md, 5.5). The dev stack's second host name can now be overridden with `EXTRA_HOST` (it stays `localhost` by default). No change to the image or the database.

## Addendum: `release-2026-11-14c` (Sign out works)

The superior's first test found that the **Sign out button did nothing on any page**. The theme's button is a form that POSTs the page's nonce to `/logout`; CTFd answers `/logout` only for GET, and its CSRF check turned the POST into "not found", so the player saw an error page and stayed signed in. Nothing in the tests had ever clicked it. Fixed in `plugins/l3mon_theme/pages/fallbacks.py` (a POST handler that signs the player out and goes to the home page; the nonce check stays; CTFd's own GET `/logout` is untouched). The same audit found that the board's flag form posts to `/board` when its script has not taken over, which also ended on "not found": it now goes back to the board. New permanent tests (`test_theme_fallbacks.py`, `test_theme_contracts.py`) check that **every form, every link and every address a script calls in the theme is answered by a route that accepts that method**, so this class of fault fails in CI and not in front of a player. No change to the image's libraries or to the database.

## Addendum: `release-2026-11-15` (found by the end-to-end test of 14 and 15 November)

- **Instances:** an instance that simply ran out its time kept its unique key, so the studio's next Start collided with it, the new container was stopped as an orphan and the expired row was handed back: the studio could not start that challenge again. The key is now freed when the time is up (on Start and on Renew). A start that fails **inside** the instancer (an image that cannot be pulled, a container that dies) used to mark the whole host down for 30 seconds, which refused every other studio's starts and showed `error` on their running instances, and the player saw the instancer's own error text (image names, addresses): it is now that challenge's failure only, with a plain message.
- **Pages:** the registration form's "privacy notice" link ended on "not found" (CTFd's own `/privacy` answers 404 until a text is set): `/privacy` and `/rules` now go to the website's pages, and `/favicon.ico` goes to the icon. The three registration steps stacked on wide screens (the stories page reused the class name `.st`): fixed in the UI source and regenerated. The registration button showed two arrows. A bad or expired invite link said "This area is for the crew only": it now says the link did not work and leads on to the join step. The crew's Anti-abuse page no longer spills sideways.
- Tests: new ones for each (the two instancer faults fail on the old code), the contract audit of 14 November stays, and a real-browser check that clicks Sign out.
